3	ОПИС ВИКОНАНОЇ РОБОТИ

3.1	Загальні відомості про систему
Назва системи: PostgreSQL.
Розробник: PostgreSQL Global Development Group.
Призначення системи: PostgreSQL — це об’єктно-реляційна система керування базами даних, призначена для зберігання, обробки та керування структурованими даними. Вона використовується у вебзастосунках, корпоративних інформаційних системах, аналітичних платформах, фінансових системах, системах електронної комерції, геоінформаційних сервісах та інших програмних продуктах, де необхідна надійна робота з даними.
Основними користувачами PostgreSQL є:
	адміністратори баз даних;
	backend-розробники;
	аналітики даних;
	DevOps-інженери;
	корпоративні інформаційні системи;
	вебзастосунки та серверні сервіси.
	Основні функції PostgreSQL:
	створення та керування базами даних;
	виконання SQL-запитів;
	підтримка транзакцій;
	забезпечення цілісності даних;
	індексація та оптимізація запитів;
	керування користувачами та правами доступу;
	резервне копіювання та відновлення;
	реплікація даних;
	підтримка розширень.
Основні функції PostgreSQL:

3.2	Архітектурний стиль системи
Основне призначення: Відокремлення абстракції від її реалізації таким чином, щоб вони могли змінюватися та розвиватися незалежно одна від
одної. PostgreSQL має клієнт-серверну архітектуру з елементами багатошарової та компонентної архітектури.
Основним архітектурним стилем є клієнт-серверна архітектура, оскільки користувацькі застосунки або клієнтські інструменти звертаються до серверного процесу PostgreSQL, який обробляє запити, працює з даними та повертає результат.
Також у PostgreSQL можна виділити ознаки багатошарової архітектури, оскільки система має окремі логічні рівні:
	рівень клієнтської взаємодії;
	рівень обробки запитів;
	рівень планування та оптимізації;
	рівень виконання запитів;
	рівень керування транзакціями;
	рівень зберігання даних.
Компонентний підхід проявляється у тому, що PostgreSQL складається з окремих підсистем: парсер SQL, оптимізатор, виконавець запитів, менеджер транзакцій, буферний менеджер, WAL-журнал, система зберігання, індекси та розширення.
Обґрунтування вибору архітектури:
Клієнт-серверний стиль дозволяє централізовано зберігати дані, контролювати доступ, обробляти багато одночасних підключень і забезпечувати незалежність клієнтських програм від внутрішньої реалізації зберігання даних. Такий підхід є ефективним для систем керування базами даних, оскільки сервер бере на себе всю складну логіку роботи з даними, транзакціями, блокуваннями, кешуванням і журналюванням.

3.3	Основні компоненти системи
Архітектура PostgreSQL складається з таких основних компонентів:
3.3.1 Інтерфейс користувача
Клієнтський рівень представлений програмами та інструментами, які надсилають SQL-запити до сервера PostgreSQL. До них належать:
	psql;
	pgAdmin;
	backend-застосунки;
	ORM-бібліотеки;
	API-сервери;
	BI-системи;
	скрипти автоматизації.
Клієнт взаємодіє із сервером через мережеве підключення або локальний сокет.
3.3.2 Серверна частина
Сервер PostgreSQL відповідає за приймання підключень, обробку запитів, керування процесами, транзакціями, пам’яттю та доступом до файлів бази даних.
Для кожного клієнтського підключення PostgreSQL створює окремий серверний процес, який обробляє запити цього клієнта.
3.3.3 Рівень бізнес-логіки
У контексті PostgreSQL бізнес-логіка може бути реалізована частково на рівні бази даних за допомогою:
	збережених процедур;
	функцій;
	тригерів;
	обмежень цілісності;
	правил;
	представлень;
	політик доступу.
Це дозволяє централізовано реалізовувати частину логіки обробки даних без дублювання її у різних клієнтських застосунках.
3.3.4 Рівень зберігання даних
Рівень зберігання відповідає за фізичне розміщення даних у файлах, керування сторінками пам’яті, таблицями, індексами та журналами.
До цього рівня належать:
	heap storage;
	індекси;
	buffer manager;
	write-ahead log;
	файлове сховище;
	механізми vacuum;
	механізми checkpoint.
3.3.5 Допоміжні сервіси
До допоміжних підсистем PostgreSQL належать:
	autovacuum;
	background writer;
	WAL writer;
	checkpointer;
	replication process;
	statistics collector;
	extension manager.
Ці компоненти підтримують стабільну роботу сервера, оптимізують використання ресурсів і забезпечують надійність зберігання даних.
3.4 Взаємодія компонентів
Загальна схема взаємодії компонентів PostgreSQL виглядає так:
1.	Клієнтський застосунок надсилає SQL-запит до сервера PostgreSQL.
2.	Сервер приймає підключення та передає запит на обробку.
3.	Парсер перевіряє синтаксис SQL-запиту.
4.	Аналізатор перевіряє коректність об’єктів бази даних.
5.	Оптимізатор формує оптимальний план виконання.
6.	Виконавець запиту реалізує план.
7.	Менеджер транзакцій контролює цілісність операцій.
8.	Буферний менеджер працює з кешем сторінок.
9.	Система зберігання читає або записує дані.
10.	Результат повертається клієнту.
Основні протоколи та механізми взаємодії:
	SQL як мова запитів;
	PostgreSQL frontend/backend protocol;
	TCP/IP або Unix socket;
	транзакційний механізм ACID;
	MVCC для паралельного доступу;
	WAL для журналювання змін;
	блокування для синхронізації доступу;
	реплікація для передавання змін між серверами.
Опис UML-діаграми компонентів:
На компонентній діаграмі PostgreSQL можна виділити такі елементи:
	Client Application;
	PostgreSQL Server;
	Connection Manager;
	SQL Parser;
	Query Optimizer;
	Query Executor;
	Transaction Manager;
	Buffer Manager;
	Storage Manager;
	WAL Manager;
	Database Files.
Клієнтський застосунок взаємодіє із PostgreSQL Server. Сервер передає запит до Parser, після чого запит обробляється Optimizer та Executor. Executor звертається до Transaction Manager, Buffer Manager і Storage Manager. Зміни фіксуються через WAL Manager у журналі транзакцій.
Опис UML-діаграми послідовності:
На діаграмі послідовності показано процес виконання SQL-запиту. Клієнт надсилає SQL-запит серверу, сервер аналізує його, створює план виконання, звертається до сховища даних, виконує транзакційні перевірки та повертає результат клієнту.
3.5 Масштабованість та надійність
PostgreSQL має низку механізмів для забезпечення масштабованості та надійності.
Масштабованість PostgreSQL забезпечується такими засобами:
	вертикальне масштабування серверних ресурсів;
	індексація таблиць;
	оптимізація SQL-запитів;
	секціонування таблиць;
	реплікація читання;
	connection pooling;
	кешування результатів на рівні застосунку;
	використання зовнішніх балансувальників навантаження.
Для великих систем PostgreSQL часто використовується разом із PgBouncer, HAProxy, Patroni або іншими інструментами для керування підключеннями, балансуванням і високою доступністю.
Надійність PostgreSQL забезпечується такими механізмами:
	транзакції ACID;
	журнал попереднього запису WAL;
	механізм checkpoint;
	резервне копіювання;
	streaming replication;
	point-in-time recovery;
	контроль цілісності даних;
	механізм MVCC;
	автоматичне очищення старих версій рядків через autovacuum.
PostgreSQL може бути частиною відмовостійкої інфраструктури. Для цього використовуються:
	primary/replica replication;
	автоматичне перемикання на резервний сервер;
	резервне копіювання;
	моніторинг стану сервера;
	дублювання критичних компонентів.
PostgreSQL використовує власний буферний кеш shared buffers, а також може користуватися кешем операційної системи. Це дозволяє зменшити кількість фізичних звернень до диска та підвищити продуктивність.
Контейнеризація та хмарна інфраструктура
PostgreSQL може запускатися у контейнерах Docker, у Kubernetes-кластерах або в хмарних сервісах. У хмарній інфраструктурі часто використовуються керовані сервіси PostgreSQL, які автоматизують резервне копіювання, моніторинг, масштабування та оновлення.
3.6 Приклади програмної реалізації
Для демонстрації архітектурних принципів PostgreSQL можна розглянути приклад взаємодії клієнтського застосунку із сервером бази даних.
Приклад SQL-запиту:
1 CREATE TABLE users (
2 id SERIAL PRIMARY KEY,
3 username VARCHAR(100) NOT NULL,
4 email VARCHAR(150) UNIQUE NOT NULL
5 );
6
7 INSERT INTO users (username, email)
8 VALUES ('user1', 'user1@example.com');
9
10 SELECT id, username, email
11 FROM users
12 WHERE username = 'user1';

У цьому прикладі клієнтський застосунок надсилає SQL-запит до PostgreSQL Server. Сервер перевіряє синтаксис, оптимізує виконання, звертається до рівня зберігання даних і повертає результат.
Приклад підключення до PostgreSQL з Node.js:
1 import pg from 'pg';
2
3 const { Client } = pg;
4
5 const client = new Client({
6 host: 'localhost',
7 port: 5432,
8 database: 'example_db',
9 user: 'postgres',
10 password: 'password'
11 });
12
13 await client.connect();
14
15 const result = await client.query(
16 'SELECT id, username, email FROM users WHERE username = $1',
17 ['user1']
18 );
19
20 console.log(result.rows);
21
22 await client.end();

У результаті виконання практичного заняття було досліджено архітектуру програмної системи PostgreSQL.
